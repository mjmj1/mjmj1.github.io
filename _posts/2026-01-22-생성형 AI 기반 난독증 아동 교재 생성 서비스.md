## 기술 선택 배경 / 기획 의도
- 난독증 아동이 겪는 주요 어려움이 단순한 학습 의지 부족이 아니라, **텍스트 인식과 처리 과정의 부담**에서 비롯된다는 점에 주목함
- 난독증 아동용 학습 콘텐츠가 일반 아동 대비 턱없이 부족하고, 시간과 비용도 크기 때문에 주제를 선택하게 됨

## 책임 및 기여
- **교재 생성 데이터 구조 설계**  
  Document, Textbook, Page 구조로 이어지는 교재 생성 흐름을 정의하고 페이지 단위 학습 데이터를 저장하기 위한 관계형 데이터베이스 모델 설계
- **PDF 기반 텍스트 추출 파이프라인 구현**  
  AWS S3에 저장된 PDF 파일을 기반으로 PDFBox를 활용하여 페이지 단위 텍스트를 추출하는 파싱 로직 구현
- **문서 처리 파이프라인 설계**  
  PDF 업로드 이후 교재 및 페이지 데이터로 변환되는 백엔드 처리 흐름 설계
- **교재 생성 REST API 구현**  
  교재 생성, 저장, 조회 기능을 담당하는 Spring Boot 기반 REST API 설계 및 구현
- **번역 프롬프트 엔지니어링**  
  생성형 AI를 통한 영어 -> 한국어 번역 프롬프트 설계

### 1. 문서 업로드 기반 교재 생성 파이프라인 설계
PDF 업로드 이후 `Document` → `Textbook` → `Page` 구조로 이어지는 교재 생성 흐름을 설계하고 구현  
문서 업로드 요청 시 `Document` 엔티티를 생성하여 파일 메타데이터를 저장하고 이후 교재 생성 단계로 연결되는 구조를 구성

``` java
@Transactional
public DocumentDto uploadDocument(
        Long guardianId,
        MultipartFile file,
        String title
) throws IOException {

    Guardian guardian =
        guardianRepository.findById(guardianId)
            .orElseThrow(
                () -> new ApplicationException(
                    ExceptionCode.GUARDIAN_NOT_FOUND
                )
            );

    Document document =
        Document.builder()
            .guardian(guardian)
            .title(title)
            .originalFilename(
                file.getOriginalFilename()
            )
            .filePath(
                "temp_" + System.currentTimeMillis()
            )
            .fileSize(file.getSize())
            .mimeType(file.getContentType())
            .build();

    document =
        documentRepository.save(document);
```
#### 코드 설명
- 파일 저장 이전 `Document` 엔티티를 생성하여 파일 메타데이터 관리 구조 확보
- `Document` 중심 교재 생성 파이프라인 구성
- 이후 `Textbook` 및 `Page` 생성 흐름과 연결 가능한 구조 설계

#### 처리 흐름
```
PDF 업로드
→ Document 생성
→ S3 저장
→ PDF 페이지 파싱
→ Textbook 생성
```

### 2. AWS S3 기반 PDF 저장 구조 구현
파일을 로컬 서버가 아닌 S3에 저장하여 문서 처리 시스템과 파일 저장 시스템을 분리

``` java
String s3Key =
    String.format(
        "%d/%d/%s",
        guardianId,
        documentId,
        uniqueFilename
    );

ObjectMetadata metadata =
    new ObjectMetadata();

metadata.setContentLength(
    file.getSize()
);

metadata.setContentType(
    file.getContentType()
);

metadata.setContentDisposition(
    "inline; filename=\"" +
    uniqueFilename +
    "\""
);

amazonS3Client.putObject(
    bucketName,
    s3Key,
    file.getInputStream(),
    metadata
);
```
#### 코드 설명
- `guardianId` / `documentId` 기준 계층형 저장 구조 설계
- 문서 식별자 기반 파일 접근 구조 구성
- 교재 생성 이후 재사용 가능한 파일 저장 구조 확보

### 3. PDF 페이지 단위 텍스트 추출 파싱 구조 구현
PDF 전체 문서를 하나의 텍스트로 처리하지 않고 페이지 단위 학습 콘텐츠로 활용하기 위한 파싱 구조 구현

``` java
URL url =
    new URL(s3Url);

try (
    InputStream inputStream =
        url.openStream()
) {

    document =
        PDDocument.load(
            inputStream
        );
}

PDFTextStripper stripper =
    new PDFTextStripper();

int pageCount =
    document.getNumberOfPages();

for (int i = 1;
     i <= pageCount;
     i++) {

    stripper.setStartPage(i);

    stripper.setEndPage(i);

    String pageText =
        stripper.getText(
            document
        );

    pages.add(
        pageText
    );
}
```
#### 코드 설명
- 페이지 단위 콘텐츠 생성 구조 지원
- 페이지 단위 분석 확장 가능 구조 확보
- 이후 학습 콘텐츠 저장 구조와 연결 가능하도록 설계

#### 데이터 변환 흐름
```
PDF
→ InputStream 로딩
→ PDDocument 생성
→ 페이지 반복 처리
→ List<String> 변환
```

### 5. 교재 생성 REST API 설계 및 구현
MultipartFile 기반 PDF 업로드 API 구현

``` java
@PostMapping(
    value =
        "/documents/upload",
    consumes =
        MediaType.MULTIPART_FORM_DATA_VALUE
)

public ResponseEntity<
        CommonResponse<DocumentDto>
> uploadDocument(
    @RequestParam("guardianId")
    Long guardianId,
    @RequestParam("file")
    MultipartFile file,
    @RequestParam("title")
    String title

) throws IOException {

    DocumentDto dto =
        convertProcessService
            .uploadDocument(
                guardianId,
                file,
                title
            );

    return ResponseEntity.ok(

        new CommonResponse<>(
            "PDF 업로드 완료",
            dto
        )
    );
}
```
#### 코드 설명
- MultipartFile 기반 파일 업로드 처리 구조 설계
- 파일 확장자 검증 구조 적용
- 서비스 계층 중심 책임 분리 구조 설계
- 교재 생성 파이프라인과 API 흐름 연결

#### API 처리 흐름
```
Client 요청
→ Controller
→ Service
→ Repository
→ S3 저장
→ PDF 파싱
```
