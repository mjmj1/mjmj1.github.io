### 개선 방향 및 학습한 점

1. **물리 엔진 제어**
   - 로프 시스템 구현 당시에 단순히 매달리는 것을 넘어 플레이어의 입력으로 그네처럼 반동을 주는 기능이 필요했음
   - `HingeJoint2D`로 연결된 세그먼트에 플레이어를 종속시키고, 입력 방향에 따라 힘을 가해 물리적인 스윙을 구현함
2. **코루틴을 활용한 상태 관리**
   - 몬스터의 상태(순찰, 추격 등)를 관리할 때, 복잡한 클래스 구조 대신 코루틴을 활용해 상태 전환을 처리함  
     게임잼이라는 빠른 호흡의 개발 환경에서 코드 복잡도를 낮추면서도 비동기적인 동작을 제어하는 경험을 함

### 기술적 한계와 문제점

1. **로프 물리 안정화 문제**
   - 로프 세그먼트가 많아질수록 물리 연산량이 늘어나고, 고속 이동 시 세그먼트 사이가 벌어지거나 뚫고 지나가는 현상이 발생함
   - `HingeJoint2D`의 `useLimits`와 `Rigidbody2D`의 질량 중심을 조절하여 완화했으나, 더 안정적인 거동을 위해서는 Verlet Integration 같은 커스텀 물리 로직 도입을 고려해볼 필요가 있었음.

2. **인스펙터 과잉 설계의 역효과**
   - 기획자가 코드를 수정하지 않고도 자유롭게 레벨을 구성할 수 있도록 `Monster`나 `Interactable`의 세부 속성을 인스펙터에 모두 노출함
   - 하지만 선택지가 너무 많아지자, 오히려 기획자가 어떤 변수를 건드려야 하는지 혼란스러워함
   - 단순 변수 노출(`[SerializeField]`)을 넘어서 커스텀 에디터를 활용해 현재 모드에 필요한 옵션만 보여주는 등 개발 도구로서의 UX도 고려해야 함을 배움

## 구현 상세 및 핵심 로직

### PlayerClimb.cs

##### **개요**

'오르는 행위'를 추상화하여 사다리와 로프를 하나의 등반 로직으로 통합함  
`BaseInteractable`을 상속받은 대상(`Ladder` vs `Rope`)을 `currentClimbable` 변수에 할당하는 방식으로 코드를 재사용함  
로프는 '스윙'이라는 특수 물리가 필요하므로 별도의 분기 처리를 통해 물리 힘을 적용함

> **처리 흐름**  
> 상호작용 시도 (`Ladder` or `Rope`)
> → `currentClimbable` 변수에 대상 할당 (공통)
> → `HandleClimbing()`에서 수직 이동 처리 (공통)
> → 로프일 경우 `RopeTick()`을 통해 스윙 물리 연산 추가 수행

##### **핵심 코드**

```csharp
// 등반 로직 통합 (사다리/로프 공용)
private void HandleClimbing()
{
    if (!IsClimbing || !currentClimbable) return;

    var v = inputHandler.MoveInput.y;
    // ... 수직 이동 및 위치 보정 로직 (공통)
}

// 로프 전용 물리 처리 (스윙)
private void RopeTick()
{
    // ... 로프일 때만 호출됨
    var x = inputHandler.MoveInput.x;
    if (Mathf.Abs(x) > 0.01f)
    {
        // 로프 세그먼트에 물리 힘을 가해 반동 구현
        ropeBody.AddForceAtPosition(forceDir * ropeKickImpulse, ...);
    }
}
```

##### **설계 의도 / 코드 설명**

- 사다리와 로프 모두 '위아래로 이동하고 특정 위치에 고정된다'는 공통점에 착안해 `HandleClimbing` 하나로 통합하여 코드 중복을 줄임.
- 공통 로직 외에 로프만의 '흔들림'을 구현하기 위해 RopeTick을 분리하고, 애니메이션 시스템에서도 `SelectClimbAnimSet`을 통해 로프 여부를 판단하여 다른 모션을 재생하도록 설계함

### PlayerClimb.cs

##### **개요**

몬스터의 행동 패턴을 상태(State)로 정의하고, 각 상태를 코루틴으로 구현하여 관리함  
ISwitch 인터페이스를 구현하여, 외부 장치(버튼, 레버)에 의해 몬스터의 상태가 강제로 변경될 수 있도록 설계함

##### **핵심 코드**

```csharp
public class Monster : MonoBehaviour, ISwitch
{
    // 외부 스위치 작동 시 호출 (ISwitch 인터페이스 구현)
    public void OnSwitch()
    {
        switch (targetMode)
        {
            case MonsterMode.Patrol: StartPatrol(); break;
            case MonsterMode.Chase: StartChase(); break;
            // ...
        }
    }

    private IEnumerator PatrolCo()
    {
        while (mode == MonsterMode.Patrol)
        {
            // ... 지정된 범위 왕복 이동 로직
            yield return wait;
        }
    }
}
```

##### **설계 의도 / 코드 설명**

- 몬스터를 단순한 적으로만 두지 않고 ISwitch를 상속받게 하여, 플레이어가 버튼을 눌러 몬스터를 유인하거나 가두는 퍼즐 요소를 구현할 수 있도록 함
- FixedUpdate에서 복잡한 분기문을 쓰는 대신 코루틴을 사용하여 이동 로직과 대기 시간을 직관적으로 작성함
