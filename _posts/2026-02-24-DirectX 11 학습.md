## 강의 1: 렌더링 파이프라인 1

### 개요
3차원 데이터를 2차원으로 변환하는 과정에는 무수히 많은 과정이 있는데, 이런 복잡한 과정을 거쳐 데이터를 가공할 땐 하나의 파이프라인을 구성해야 함

**파이프라인이란?**
- 여러 명령어가 중첩되어서 프로그램이나 하나의 작업을 수행하게 하는 과정(연산들의 집합)
- 한 사이클 안에 많은 과정이 존재하기 때문에 복잡해지거나 사용자가 어려워질 수 있는 단점이 있다

렌더링 파이프라인엔 다양한 방법이 존재하는데 이번 강의에선 레스터라이제이션 파이프라인을 사용함

![](https://oopy.lazyrockets.com/api/v2/notion/image?src=https%3A%2F%2Fprod-files-secure.s3.us-west-2.amazonaws.com%2Fcc7962ab-bf9b-46ae-bfcc-f6a88421e46b%2F1f072a48-90c3-41fe-a88b-bae6c817fe1c%2FUntitled.png&blockId=1de0b1ff-a61e-8028-b347-fd8b998e978d)_레스터라이제이션 파이프라인_

### 1. input Assembly

3차원 모델 하나를 3차원 세상에 나타내기 위해서 가장 먼저 해줘야 할 것은 무엇인가?

모델은 점(vertex)로 이루어져 있음 -> **폴리곤(점들의 집합)**이라고 한다

게임에선 삼각형으로 3D 폴리곤을 정의하는데, 이때 이 정점 데이터들을 운반하는 자료구조를 **Vertex Buffer**라고 부름

게임을 시작하면 RAM에 정점들이 먼저 로드되고, 이 데이터를 연산하기 위해 GPU로 복사하여 옮기는 과정에서 GPU에 정점들을 넣을 공간을 만드는데, 이 공간을 **Vertex Buffer**라고 부름

또한 GPU에 정점을 이용하여 어떻게 그릴지를 정의한 파이프라인의 메모리 공간도 존재하게 됨

즉 GPU를 이용하여 화면을 렌더링할 때 모든 정보들이 GPU로 넘어가게 됨

Vertex Buffer와 같이 등장하는 용어로 Index Buffer가 있음

**Index Buffer**는 정점들의 인덱스를 저장하고 있는 버퍼
예를 들면 사각형을 삼각형 기반으로 그리기 위해선 2\*3 = 6개의 정점이 필요함

![](https://learn.microsoft.com/ko-kr/windows/win32/direct3d9/images/dip-fig1.png){: width="200"}

사각형을 구성하는 정점을 4개만 두고 4개를 한 붓 그리기처럼 중복해서 그려주는 방식을 사용하는 것이 인덱스 버퍼의 기능라고 할 수 있음, 하지만 없어도 상관없음

![](https://learn.microsoft.com/ko-kr/windows/win32/direct3d9/images/dip-fig4.png){: width="400"}

추가적으로 인덱스 버퍼를 사용하는데, 결국 메모리를 사용하니까 똑같다고 생각할 수 있음
정점은 위치 데이터 외에도 색, 법선, 텍스쳐 좌표, 애니메이션 정보 등 다양한 데이터를 추가하여 사용하기 때문에 단순히 정수만 저장하는 인덱스 버퍼가 메모리적으로 효율적임

정점 버퍼는 단순한 정점들의 연속적인 메모리 구조에 불과하기 때문에 실제로 GPU에서 이러한 정점들을 이용하여 어떤 도형을 만들어야 하는지 정보가 필요함
해당 도형 정보를 **Primitive Topology** 라고 함

![](https://learn.microsoft.com/ko-kr/windows/win32/direct3d11/images/d3d10-primitive-topologies.png)
_Primitive Topology_

결론적으로 Input Assembler는 이러한 정점들의 데이터를 읽고, 삼각형과 같은 도형으로 조립하는 단계의 일을 한다고 생각하면 됨

### 2. Vertex Shader

Input Assembler에서 받은 정점들의 정보로 도형은 생성되었지만, 로컬 좌표계에 있기 때문에 해당 데이터들을 화면에 출력하면 화면 중심부에 전부 출력되기 때문에 공간 좌표계(World)로 변환할 필요가 있음

Local Space에서 World Space로 변환이 필요하고, 실제 플레이어가 바라보는 카메라가 중심이 되는 공간 View Space 변환을 해줌. 그리고 마지막 Projection 변환을 거쳐 최종적으로 정의된 Clip Space로 변환해줌

#### 2.1. 월드 공간 변환
Local Space는 3차원 세상에서 표현될 개인의 공간에 정의된 영역

#### 2.2. 카메라 공간 변환
월드 공간 변환이 완료된 물체를 가상의 카메라로 볼 수 있는 영역의 공간을 뷰 공간이라고 함
월드 공간의 모든 물체를 카메라 공간으로 변환하면 효율적으로 효과나 렌더링을 진행할 수 있음

![](https://oopy.lazyrockets.com/api/v2/notion/image?src=https%3A%2F%2Fprod-files-secure.s3.us-west-2.amazonaws.com%2Fcc7962ab-bf9b-46ae-bfcc-f6a88421e46b%2F1574f18b-52db-48b9-830d-1afafadd2ad3%2FUntitled.png&blockId=1de0b1ff-a61e-80d0-a304-f04184ea4f67)

가상의 카메라에 비쳐지는 FOV(시야각), Aspect(종횡비)에 의해 결정되는 가시 영역을 **View Volumn** 이라고 함
이렇게 생성된 뷰 볼륨에 Near, Far 정보가 전달되어 절두체의 영역을 다시 정의함

![](https://oopy.lazyrockets.com/api/v2/notion/image?src=https%3A%2F%2Fprod-files-secure.s3.us-west-2.amazonaws.com%2Fcc7962ab-bf9b-46ae-bfcc-f6a88421e46b%2Fe34c1748-0b9d-4ef9-bf9a-9d727c72f176%2FUntitled.png&blockId=1de0b1ff-a61e-80af-9b5b-e5f926ec9de5)

#### 2.3. View Frustrum (절두체)

절두체 안에 있는 데이터만 그려지게 되는데, 이 과정을 **클리핑(Cliping)**이라고 함
이 클리핑은 카메라 변환에서 이뤄지지 않고 추후 클립 공간에서 레스터라이저로 넘겨질 때 수행됨

#### 2.4. 투영 변환
카메라 변환까지 완료하면 월드의 모든 물체를 카메라 공간으로 변환되어 가상의 카메라를 통해 바라볼 수 있게 되는데, 최종적으로 바라봐야할 공간은 2D인 모니터가 됨

3D를 2D 평면으로 표현하는 방법은 원근법을 이용하게 됨

투영 변환은 원근법을 구현하기 위해 카메라 공간에 정의된 절두체를 3차원 클립 공간으로 변환하는 것을 의미함

여기서 투영 변환은 3D 물체를 2D 평면으로 바꾸는게 아닌 3D 물체로 변형됨
카메라 공간은 복잡한 육면체의 형태기 때문에 연산이 복잡해지는 것을 방지하기 위해 우선 클립 공간으로 변환하는 과정을 한 번 더 거치게 됨

![](https://oopy.lazyrockets.com/api/v2/notion/image?src=https%3A%2F%2Fprod-files-secure.s3.us-west-2.amazonaws.com%2Fcc7962ab-bf9b-46ae-bfcc-f6a88421e46b%2F39c1187d-f2ef-4d0e-b256-0d1b27dcddde%2FUntitled.png&blockId=1de0b1ff-a61e-8019-a9ae-d913a0bafe03)
