### 개선 방향 및 학습한 점

1. **협업 중심 설계의 중요성**

   - 확장성을 고려해 `Thrower`와 `Interactable`을 기반으로 **상속 구조를 설계**했으나 정작 팀원들이 **구조를 이해하고 활용하는 데 어려움**을 겪음
   - 기술을 활용한 패턴이라도 팀원들이 직관적으로 사용하기 어렵다면 **오히려 협업에 방해가 될 수 있음**을 알게 됨
   - 기술적 고도화보다는 '문서화가 필요 없는 **직관적인 코드**', '누구나 **쉽게 쓸 수 있는 인터페이스**'를 설계하는 것이 우선되야함을 깨달음

2. **싱글톤과 생명주기 관리**

   - `StageManager`, `GameManager` 등을 싱글톤으로 관리하여 접근성은 높였으나, 씬 전환 시 `DontDestroyOnLoad`로 인해 **객체가 중복 생성**되는 문제를 겪음
   - 이를 해결하며 올바른 초기화 패턴을 정립함

3. **사용자 피드백 강화**
   - 단순히 던지는 행위 외에 `LineDrawer`를 통해 예상 궤적을 시각화하고, `ZoomView`로 클리어 순간을 캡처하는 등 **UX/UI 요소를 강화하여 게임의 완성도**를 높임

### 기술적 한계와 문제점

1. **과도한 추상화**

   - 확장성에 집중한 나머지 로직의 분산도가 높아져, 팀원들이 **코드 흐름을 한눈에 파악하기 어려워함**
   - 단순한 기믹 추가 시에도 부모-자식 관계와 오버라이딩 규칙을 이해해야 했기에 팀원들의 **작업 속도가 저하되는 현상**이 발생함
   - 프로젝트 규모와 팀 역량에 맞는 **적정 기술 선택의 중요성**을 알게 됨

2. **데이터 하드코딩**
   - `StageManager`에서 `List<GameObject>` 형태로 프리팹을 직접 할당하여 스테이지를 관리하고 있어 유연성이 떨어짐
   - 추후 ScriptableObject나 JSON 데이터를 통해 스테이지 정보를 외부에서 로드하는 방식으로 리팩토링이 필요함

## 구현 상세 및 핵심 로직

### Thrower.cs

##### **개요**

게임의 핵심 메커니즘인 '던지기'를 담당하는 최상위 클래스  
`InputSystem`의 이벤트를 구독하여 마우스 드래그 거리만큼 힘을 계산하고, 실제 발사는 이벤트를 통해 자식 클래스나 외부 리스너에게 위임하는 **템플릿 메서드 패턴** 형태

> **처리 흐름**  
> **Input Event 수신 (Down/Hold/Up)**
> → 드래그 벡터 계산 (방향, 크기)
> → `Mathf.InverseLerp`로 힘 정규화
> → `OnThrow` 이벤트 발생

##### **핵심 코드**

```csharp
protected virtual void OnMouseButtonHold(Vector2 mousePosition)
{
    if (IsThrown) return;

    var offset = _startPosition - mousePosition;

    ThrowDirection = offset.normalized;

    // 드래그 거리에 비례하여 힘 계산 (0 ~ 1000 사이의 거리를 0~1로 매핑 후 maxThrowForce 적용)
    ThrowForce = Mathf.InverseLerp(0, 1000, offset.magnitude) * maxThrowForce;
}

protected virtual void OnMouseButtonUp(Vector2 mousePosition)
{
    IsThrown = true;
    if (SoundManager.Instance) SoundManager.Instance.StopSFX("sound_pluck");
    if (SoundManager.Instance) SoundManager.Instance.Play_R_SFX("sound_throw_", 2);
    OnThrow?.Invoke();
}
```

##### **설계 의도 / 코드 설명**

- Update 문에서 입력을 직접 체크하지 않고 InputSystem의 이벤트를 구독하여, **입력 처리 로직이 비대해지는 것을 방지**함
- `virtual` 키워드를 사용하여 `HandThrower` 등 파생 클래스에서 입력 처리 방식을 재정의할 수 있도록 열어둠

### Throwable.cs & Interactable.cs

##### **핵심 로직 개요**

던져지는 물체(Throwable)와 닿는 물체(Interactable) 간의 상호작용을 처리함  
Throwable은 물리적 특성(탄성, 회전)을 관리하고, 충돌 시 상대방의 Interact 메서드를 호출하여 구체적인 게임 로직(점수 획득, 케이크 장식 등)을 실행함

##### **핵심 코드**

```csharp
// Throwable.cs
protected virtual void OnCollisionEnter2D(Collision2D collision)
{
    // ... (실패 조건 체크)

    if (!collision.collider.CompareTag("Target")) return;

    var interactable = collision.collider.GetComponent<Interactable>();

    interactable.Interact(collision); // 상대방의 상호작용 로직 실행

    Interact(); // 자신의 상호작용 로직 실행 (예: 멈춤)
}
```

```csharp
// Cake.cs (Interactable 구현체)
public override void Interact(Collision2D collision)
{
    var contactPoint = collision.GetContact(0).point;
    SpawnCream(contactPoint); // 충돌 지점에 크림 생성
}
```

##### **설계 의도 / 코드 설명**

- Throwable은 자신이 무엇과 부딪혔는지만 알면 되고, 그 결과로 어떤 일이 일어나는지는 Interactable 구현체(Cake, MakeBurger 등)에게 위임함
- 새로운 기믹(예: 부딪히면 터지는 풍선)을 추가할 때 기존 투척 코드를 수정할 필요 없이 Interactable을 상속받는 새 클래스만 작성하면 됨

### StageManager.cs

##### **핵심 로직 개요**

일반 스테이지(물건 던지기)와 보너스 스테이지(케이크 꾸미기)가 번갈아 나타나는 게임의 전체 흐름을 관리함  
현재 스테이지 인덱스에 따라 적절한 Thrower와 Interactable을 인스턴스화하고 카메라를 세팅함

##### 핵심 코드

```csharp
public void StageStart()
{
    SetRandomCameraBackgroundColor();

    // ... (All Clear 체크)

    if (IsCakeStage() && currentCakeStage < cakeThrowerList.Count)
    {
        cake.gameObject.SetActive(true);
        currentInteractable = cake;
        currentThrower = Instantiate(cakeThrowerList[currentCakeStage]).GetComponent<Thrower>();
    }
    else if (_currentStage < throwerList.Count)
    {
        currentInteractable = Instantiate(interactableList[_currentStage]).GetComponent<Interactable>();
        currentThrower = Instantiate(throwerList[_currentStage]).GetComponent<Thrower>();
    }
    // ...
}
```

##### **설계 의도 / 코드 설명**

- allStage % 2 == 0 조건을 이용해 짝수/홀수 스테이지마다 다른 게임 모드를 제공하여 플레이어의 지루함을 방지함
- 미리 씬에 배치하지 않고 프리팹 리스트에서 그때그때 필요한 객체를 생성하여 메모리 낭비를 줄이고 초기화를 명확하게 함
