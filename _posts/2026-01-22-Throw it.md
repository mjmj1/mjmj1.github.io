### 개선 방향 및 학습한 점

1. **협업 중심 설계의 중요성**
   - 확장성을 고려해 `Thrower`와 `Interactable`을 기반으로 상속 구조를 설계했으나 정작 팀원들이 구조를 이해하고 활용하는 데 어려움을 겪음
   - 기술을 활용한 패턴이라도 팀원들이 직관적으로 사용하기 어렵다면 오히려 협업에 방해가 될 수 있음을 알게 됨
   - 기술적 고도화보다는 '문서화가 필요 없는 직관적인 코드', '누구나 쉽게 가져다 쓸 수 있는 인터페이스'를 설계하는 것이 우선되야함을 깨달음

2. **싱글톤과 생명주기 관리**
   - `StageManager`, `GameManager` 등을 싱글톤으로 관리하여 접근성은 높였으나, 씬 전환 시 `DontDestroyOnLoad`로 인해 객체가 중복 생성되는 문제를 겪음  
     이를 해결하며 올바른 초기화 패턴을 정립함

3. **사용자 피드백 강화**
   - 단순히 던지는 행위 외에 `LineDrawer`를 통해 예상 궤적을 시각화하고, `ZoomView`로 클리어 순간을 캡처하는 등 UX/UI 요소를 강화하여 게임의 완성도를 높임

### 기술적 한계와 문제점

1. **과도한 추상화**
   - 확장성에 집중한 나머지 로직의 분산도가 높아져, 팀원들이 코드 흐름을 한눈에 파악하기 어려워함
   - 단순한 기믹 추가 시에도 부모-자식 관계와 오버라이딩 규칙을 이해해야 했기에, 팀원들의 작업 속도가 저하되는 현상이 발생함
   - 프로젝트 규모와 팀 역량에 맞는 적정 기술 선택의 중요성을 알게 됨

2. **데이터 하드코딩**
   - `StageManager`에서 `List<GameObject>` 형태로 프리팹을 직접 할당하여 스테이지를 관리하고 있어 유연성이 떨어짐
   - 추후 ScriptableObject나 JSON 데이터를 통해 스테이지 정보를 외부에서 로드하는 방식으로 리팩토링이 필요함

## 구현 상세 및 핵심 로직

### Thrower.cs

#### 핵심 로직 개요

게임의 핵심 메커니즘인 '던지기'를 담당하는 최상위 클래스  

 `InputSystem`의 이벤트를 구독하여 마우스 드래그 거리만큼 힘을 계산하고, 실제 발사는 이벤트를 통해 자식 클래스나 외부 리스너에게 위임하는 템플릿 메서드 패턴 형태

> **처리 흐름**
> Input Event 수신 (Down/Hold/Up)
>   → 드래그 벡터 계산 (방향, 크기)
>   → `Mathf.InverseLerp`로 힘 정규화
>   → `OnThrow` 이벤트 발생

#### 1. Input System

##### 핵심 코드

```csharp
protected virtual void OnMouseButtonHold(Vector2 mousePosition)
{
    if (IsThrown) return;
    
    var offset = _startPosition - mousePosition;

    ThrowDirection = offset.normalized;
    
    // 드래그 거리에 비례하여 힘 계산 (0 ~ 1000 사이의 거리를 0~1로 매핑 후 maxThrowForce 적용)
    ThrowForce = Mathf.InverseLerp(0, 1000, offset.magnitude) * maxThrowForce;
}

protected virtual void OnMouseButtonUp(Vector2 mousePosition)
{
    IsThrown = true;
    if (SoundManager.Instance) SoundManager.Instance.StopSFX("sound_pluck");
    if (SoundManager.Instance) SoundManager.Instance.Play_R_SFX("sound_throw_", 2);
    OnThrow?.Invoke();
}
```

##### **설계 의도 / 코드 설명**
- Update 문에서 입력을 직접 체크하지 않고 InputSystem의 이벤트를 구독하여, 입력 처리 로직이 비대해지는 것을 방지함
- `virtual` 키워드를 사용하여 `HandThrower` 등 파생 클래스에서 입력 처리 방식을 재정의할 수 있도록 열어둠
