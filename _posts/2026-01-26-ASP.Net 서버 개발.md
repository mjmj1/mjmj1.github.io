## 기본 개념

### ASP.NET이란?
- Microsoft에서 만든 **C# 기반 웹 서버 Framework**
- **장점**
	- OS가 자유로움
	- 빠름 (Node.js, Java Spring 보다 빠른 경우가 있음)
	- 가벼움

#### 간단한 역사
- **구시대**
	- **엔진**: .NET Framework
	- **웹 기술**: ASP.NET
	- **특징**: System.Web.dll이라는 엄청 무거운 라이브러리에 묶임
	- **단점**: IIS(윈도우 서버)가 없으면 작동을 안 함 오직 윈도우 전용
- **신시대**
	- **엔진**: .NET Core
	- **웹 기술**: ASP.NET Core
	- **특징**: 무거운 System.Web을 갖다 버리고, 가볍고 빠른 모듈형으로 새로 만듬
	- **장점**: Kestrel이라는 자체 내장 서버를 탑재해서, IIS 없이도 혼자 돌아감. 리눅스에 올릴 수 있어서 서버 비용이 감소함
- **왜 "Core"를 붙였을까?**
	- 기존의 .NET Framework와 다르기 때문에 "이건 핵심(Core)만 남기고 새로 만든 거야!" 라는 뜻으로 이름을 .NET Core라고 지음
	- 그래서 웹 프레임워크 이름도 세트로 ASP.NET Core가 됨
- **지금은 왜 그냥 ".NET 8"인가요?**
	- 마이크로소프트가 .NET Core 3.1까지 만들고 나니, 이제 구시대 유물(.NET Framework)을 쓰는 사람이 거의 없어짐
	- "이제 Core라는 딱지를 떼도 되겠다. 이게 표준이다!" 라고 선언하며 .NET 5부터는 그냥 .NET이라고 부르기 시작함

### SignalR이란?
- ASP.Net에서 실시간 대화를 담당하는 라이브러리
- 웹 소켓을 잘 포장해서 사용하기 쉽도록 만든 도구
- http는 요청에만 응답하지만, 이 라이브러리로 웹 소켓을 이용해서 실시간 통신을 지원함

## 게임 서버 예제 (SignalR 사용)
#### Program.cs
``` c#
using serverTest.Scripts.Hubs; // 👈 1단계에서 만든 파일의 namespace를 적어야 합니다!  
  
var builder = WebApplication.CreateBuilder(args);  
  
// [변경 1] 불필요한 OpenAPI(Swagger) 제거 -> SignalR 추가  
// "나 이제 실시간 통신 기능 쓸 거야" 라고 등록  
builder.Services.AddSignalR();  
  
var app = builder.Build();  
  
// [변경 2] HTTP 요청 파이프라인(MapGet 등) 제거  
// 개발 환경 체크나 HTTPS 리다이렉션은 둬도 되지만, 일단 심플하게 다 뺍니다.  
  
// [변경 3] 라우팅 설정 (SignalR Hub 연결)  
// "누가 '/game' 주소로 들어오면 GameHub가 처리해"  
app.MapHub<GameHub>("/game");  
  
// 서버 실행  
app.Run();
```

#### Gamehub.cs
``` c#
using Microsoft.AspNetCore.SignalR;
using System.Threading.Tasks;

// 네임스페이스는 프로젝트 이름에 맞춰주세요. (예: MyGameServer.Hubs)
namespace MyGameServer.Hubs
{
    public class GameHub : Hub
    {
        // 1. 유저 접속 시 (전화 연결됨)
        public override async Task OnConnectedAsync()
        {
            string id = Context.ConnectionId;
            Console.WriteLine($"[접속] 새로운 유저 등장! ID: {id}");

            // 접속한 사람에게 ID 알려주기
            await Clients.Caller.SendAsync("OnMyLogin", id);

            // 다른 사람들에게 "새 유저 왔어" 알리기
            await Clients.Others.SendAsync("OnUserJoin", id);

            await base.OnConnectedAsync();
        }

        // 2. 유저 종료 시 (전화 끊김)
        public override async Task OnDisconnectedAsync(Exception? exception)
        {
            string id = Context.ConnectionId;
            Console.WriteLine($"[퇴장] 유저 나감! ID: {id}");

            // 다른 사람들에게 "얘 나갔으니 캐릭터 지워" 알리기
            await Clients.Others.SendAsync("OnUserLeft", id);

            await base.OnDisconnectedAsync(exception);
        }

        // 3. 이동 동기화 (행동)
        // 유니티가 이 함수를 호출하면 실행됨
        public async Task SendMove(float x, float y, float z)
        {
            // 나를 뺀 다른 사람들에게 좌표 전달
            await Clients.Others.SendAsync("OnMove", Context.ConnectionId, x, y, z);
        }
    }
}
```

## SignalR 내부 구조
### 1. 🚂 트랜스포트 (Transport)
SignalR은 상황에 따라 **3가지 통신 방식 중 최적의 것을 자동으로 선택**합니다.

1. **WebSockets (최우선)**
    - **설명:** 서버와 클라이언트 사이에 전용 고속도로(TCP)를 뚫어놓는 방식
    - **특징:** 가장 빠르고, 양방향 통신이 완벽합니다.
        
2. **Server-Sent Events (SSE)**
    - **설명:** 웹 소켓이 막힌 환경(일부 기업 방화벽 등)에서 씁니다.
    - **특징:** **서버 -> 클라이언트** 전송은 빠르지만, **클라이언트 -> 서버**는 일반 HTTP 요청을 써야 해서 반쪽짜리입니다.

3. **Long Polling (최후의 수단)**
    - **설명:** 가장 원시적인 방법. 클라이언트가 "새 소식 있어?"라고 묻고, 서버는 답이 생길 때까지 붙잡고 있다가 답을 줍니다. 받자마자 다시 "또 있어?" 하고 연결합니다.
    - **특징:** 느리고 서버 부하가 크지만, **모든 브라우저와 환경에서 100% 작동**합니다.

### 2. 📦 프로토콜 (Protocol)
기본적으로 두 가지를 지원합니다.
1. **JSON (텍스트, 기본값)**
    - **장점:** 눈으로 읽을 수 있습니다. (`{"x": 10, "y": 20}`) 디버깅이 편합니다.
    - **단점:** 무겁습니다. 문자열 처리가 많아서 CPU를 씁니다.

2. **MessagePack (바이너리)**
    - **장점:** 데이터를 0과 1로 압축해서 보냅니다. JSON보다 용량이 훨씬 작고, 처리 속도가 빠릅니다.
    - **단점:** 눈으로 바로 읽을 수 없습니다.

### 3. 📡 허브 (Hub) 구조

SignalR의 핵심 철학은 **RPC (Remote Procedure Call)**입니다. "내 컴퓨터에 있는 함수처럼 보이지만, 사실은 저 멀리 있는 컴퓨터의 함수를 실행한다"는 뜻입니다.

#### 일반적인 소켓 통신 (Raw Socket)

```c#
// "MOVE"라는 문자열을 파싱(분해)해야 함. 귀찮고 에러 나기 쉬움.
if (packet.StartsWith("MOVE")) {
    var parts = packet.Split(':');
    Move(parts[1], parts[2]);
}
```

#### SignalR 방식 (RPC)

``` c#
// 그냥 함수 부르듯이 쓰면 알아서 날아감.
await Clients.Others.SendAsync("Move", 10, 20);
```

SignalR 내부에서는 이 함수 호출을 가로채서 `{"target": "Move", "arguments": [10, 20]}` 같은 메시지로 바꾼 뒤 네트워크로 쏘고, 받는 쪽에서 다시 함수로 연결해 주는 **중계소(Dispatcher)** 역할을 합니다.

## SignalR 기술 문서

### 1. 🏰 Hub 클래스

`Hub`를 상속받았을 때 사용할 수 있는 모든 도구

#### `Context`

`this.Context.`으로 접근

| **속성**                  | **타입**               | **설명**           |
| ----------------------- | -------------------- | ---------------- |
| **`ConnectionId`**      | `string`             | 접속자의 고유 식별자 (난수) |
| **`UserIdentifier`**    | `string`             | 인증된 유저 ID        |
| **`User`**              | `ClaimsPrincipal`    | 유저의 보안 주체 정보     |
| **`Items`**             | `IDictionary`        | 연결별 임시 저장소       |
| **`ConnectionAborted`** | `CancellationToken`  | 연결 취소 알림 토큰      |
| **`Features`**          | `IFeatureCollection` | HTTP 로우 레벨 기능    |
| **`Abort()`**           | `void`               | 연결 강제 종료         |
| **`GetHttpContext()`**  | `HttpContext`        | HTTP 원본 컨텍스트     |

#### `Clients`

`this.Clients.`으로 접근

| **대상**                        | **설명**                                |
| ----------------------------- | ------------------------------------- |
| **`Caller`**                  | 요청을 보낸 **나 자신**에게만                    |
| **`Others`**                  | 나를 뺀 **나머지 접속자** 전원에게                 |
| **`All`**                     | **나를 포함한** 접속자 전원에게                   |
| **`Client(connectionId)`**    | 특정 ConnectionId를 가진 **1명**에게          |
| **`Clients(ids)`**            | 특정 ConnectionId 목록에 있는 **여러 명**에게     |
| **`Group(groupName)`**        | 특정 그룹에 속한 **전원**에게                    |
| **`GroupExcept(group, ids)`** | 특정 그룹에서 **몇 명 빼고** 나머지에게              |
| **`OthersInGroup(group)`**    | 특정 그룹에서 **나 빼고** 나머지에게                |
| **`User(userId)`**            | 특정 UserIdentifier를 가진 유저에게 (모든 기기 포함) |
| **`AllExcept(ids)`**          | 특정 ID들을 제외한 전원에게                      |

#### `Group`

`this.Group`으로 접근

| **메서드**                    | **설명**      | **비고**                            |
| -------------------------- | ----------- | --------------------------------- |
| **`AddToGroupAsync`**      | 유저를 그룹에 추가  | DB와 연동되지 않음(메모리). 재접속 시 다시 넣어줘야 함 |
| **`RemoveFromGroupAsync`** | 유저를 그룹에서 제거 | 명시적으로 방을 나갈 때 사용                  |

### 2. ⚙️ Server Configuration
`Program.cs`에서 `AddSignalR(options => ...)` 안에 넣을 수 있는 값

| **옵션명**                         | **기본값** | **설명 & 튜닝 가이드**                                               |
| ------------------------------- | ------- | ------------------------------------------------------------- |
| **`ClientTimeoutInterval`**     | 30초     | 이 시간 동안 클라이언트가 조용하면 연결을 끊음                                    |
| **`KeepAliveInterval`**         | 15초     | 서버가 클라이언트에게 "살아있니?" 핑을 보내는 주기                                 |
| **`HandshakeTimeout`**          | 15초     | 최초 연결 시 악수(Handshake)가 완료되어야 하는 제한 시간                         |
| **`MaximumReceiveMessageSize`** | 32KB    | **중요!** 클라이언트가 보내는 패킷 최대 크기. 이미지나 큰 데이터를 보낸다면 늘려야 함           |
| **`StreamBufferCapacity`**      | 10      | 스트리밍 데이터 업로드 시 버퍼 크기                                          |
| **`EnableDetailedErrors`**      | false   | `true`로 하면 에러 발생 시 클라이언트에 스택 트레이스(상세 내용)를 보냄. **개발 중에만 켜세요.** |
| **`SupportedProtocols`**        | null    | 지원할 프로토콜 목록 제한 (보통 안 건드림).                                    |
