## 기술 선택 배경 / 기획 의도

- **인간을 흉내 내는 AI**  
  일반적인 술래잡기가 아닌, AI(NPC)와 플레이어(Hider)가 뒤섞여 있는 상황에서 술래(Seeker)를 속이는 '마피아' 류의 심리전을 구현하고자 함  
  이를 위해 단순한 FSM이 아닌 강화학습을 통해 인간처럼 행동하여 의심을 피하는 에이전트 개발을 목표로 함
- **구형(Spherical) 월드와 네트워크 동기화**  
  한정된 공간에서 긴장감을 높이기 위해 작은 행성 형태의 맵을 구상함
- **분산 권한 토폴로지**  
  서버가 모든 물리 연산을 전담하는 중앙 집중식 대신, 캐릭터의 이동 제어권을 각 클라이언트에게 위임하는 분산 권한 방식을 채택하여 플레이어에게 지연 없는 쾌적한 조작감을 제공하도록 함

## 책임 및 기여

- 구형 행성 중력 시스템과 이를 기반으로 한 캐릭터 이동 및 회전 로직 구현
- Unity Netcode for GameObjects와 Relay/Lobby 서비스를 이용한 방 생성, 난입, 호스트 마이그레이션 등 전체 네트워크 라이프사이클 구현
- PPO 알고리즘을 사용하여 플레이어의 행동(점프, 스핀 등)을 모방하면서도 술래에게 들키지 않도록 학습하는 Hider Agent 설계 및 구현
- 역할군(Hider, Seeker, Fighter) 시스템, 미션 수행 로직, 토네이도 이벤트 등 게임의 규칙과 흐름 제어 전반을 담당

### 개선 방향 및 학습한 점

1. **상속보다 컴포지션**  
   초기 설계 시 상속으로 기능을 확장했으나, 컴포넌트 기반으로 기능을 분리하는 것이 유지보수에 유리함을 배움
2. **네트워크 동기화 구조와 RPC의 이해**  
   지속적인 상태 공유가 필요한 데이터는 `NetworkVariable`을 사용하고, 공격이나 아이템 획득 같은 일회성 이벤트는 `RPC(Remote Procedure Call)`를 사용하여 처리해야 한다는 구조적 차이를 명확히 이해하고 적용함
3. **AI 학습 보상 설계의 중요성**  
   에이전트가 단순히 도망가는 것이 아니라 '인간처럼' 보이게 하기 위해, '의심도(Suspicion)'라는 개념을 도입하고 안전 구역 내에서 행동하도록 보상 함수를 설계함

### 기술적 한계와 문제점

1. **ML-Agents의 추론 비용**  
   Spawn은 서버(호스트)가 해야한다는 원칙 때문에 다수의 NPC가 동시에 강화학습 모델로 추론을 수행할 때 서버(호스트)의 CPU 부하가 증가하는 문제가 있음
2. **호스트 사양에 따른 AI 성능 편차**  
   AI 추론 연산이 호스트 클라이언트에서 실행되다 보니 호스트 PC의 사양에 따라 AI의 판단 속도나 반응성이 달라지는 현상을 발견함
3. **캐릭터 간 물리 충돌 처리의 어려움**  
   캐릭터끼리 부딪히면서 길을 막는 플레이를 의도했지만 네트워크 환경에서 물리 엔진이 충돌을 처리할 때, 서로의 위치를 보정하는 과정에서 캐릭터가 멀리 튕겨 나가는 현상이 발생함  
   원활한 플레이를 위해 결국 캐릭터 간 충돌을 비활성화하는 것으로 타협했으나, 추후에는 개선하고 싶음

## 구현 상세 및 핵심 로직

### HiderTrainAgent.cs

##### **개요**

ML-Agents를 기반으로 숨는 역할(Hider)을 수행하는 AI 에이전트  
시각 정보와 내부 상태 정보를 결합하여 술래를 회피하고 생존하는 최적의 전략을 학습하도록 설계됨

> **전체 처리 흐름**  
> 관측 수집 (CollectObservations) → 주변 환경 Ray Sensing → 이동 가능 여부, 쿨타임, 술래와의 관계 확인  
> 행동 결정 (OnActionReceived) → 신경망 출력값 해석 → 이동, 점프, 스핀 실행  
> 보상 계산 (HandleRewards) → 생존 보상 및 이동 보정 → 시야각 기반 회피 보상 → 의심도 관리  

#### 1. 다중 센서 기반 관측 수집

##### **핵심 코드**

``` csharp
public override void CollectObservations(VectorSensor sensor)
{
    // 이동 관련 상태 관측
    sensor.AddObservation(canMove);
    sensor.AddObservation(isGround);
    
    // 술래와의 관계 관측 (시야각 내적)
    sensor.AddObservation(GetSeekerViewDot());
    
    // 행동 리스크 관측
    sensor.AddObservation(suspicion);
}
```

##### **설계 의도 / 코드 설명**
- RayPerceptionSensor3D를 통해 물리적인 지형지물을 파악하는 동시에, 벡터 관측으로 추상적인 상태 정보를 추가 제공함
- GetSeekerViewDot을 통해 '술래가 나를 보고 있는지'에 대한 핵심 정보를 수치화하여 전달함

#### 2. 이산적 행동 처리

##### **핵심 코드**

``` csharp
public override void OnActionReceived(ActionBuffers actions)
{
    var branch = actions.DiscreteActions;
    
    // Branch 0: 이동 (정지, 전, 후, 좌, 우)
    var moveDir = Vector2.zero;
    switch (branch[0]) { ... }
    
    // Branch 1: 점프
    if (branch[1] == 1) Jump();
    
    // Branch 2: 스핀 (대시)
    if (branch[2] == 1) Spin();
}
```

##### **설계 의도 / 코드 설명**
- 행동 공간을 여러 브랜치(이동, 점프, 스킬)로 나누어 동시에 여러 동작을 수행할 수 있게 함
- 행동의 가짓수가 제한되어 있어 연속적인 값 대신 이산적인 값을 사용하여 학습 효율성과 수렴 속도를 높임

#### 3. 정교한 보상 설계를 통한 행동 유도

##### **핵심 코드**

```csharp
private void HandleRewards()
{
    // 이동 중일 때 정면을 바라보고 이동하는지 확인 (자연스러운 움직임 유도)
    if (rBody.linearVelocity.magnitude > 0.005f)
    {
        var gravityDir = -planet.GetGravityDirection(transform.position).normalized;
        var tangentVelocity = Vector3.ProjectOnPlane(rBody.linearVelocity.normalized, gravityDir).normalized;
        var tangentForward = Vector3.ProjectOnPlane(transform.forward, gravityDir).normalized;

        var alignment = Vector3.Dot(tangentForward, tangentVelocity);

        if (alignment > 0.95f) AddReward(0.0005f); // 정면 이동 보상
    }

    // 술래가 시야에 들어왔는지 확인
    var dot = GetSeekerViewDot();
    if (dot >= 0f)
    {
        if (dot > 0.8f) AddReward(-0.001f); // 술래 정면에 있으면 벌점
        else if (dot < 0.5f) AddReward(0.001f); // 술래 시야 밖이면 보상
    }

    HandleSuspicion(); // 의심도 관리
    RewardIdle();      // 자연스러운 대기 상태 보상
}

private void HandleSuspicion()
{
    // 의심도가 너무 높거나 낮지 않게 유지 (인간과 유사한 패턴)
    if (suspicion < suspicionSafeZone.x || suspicion > suspicionSafeZone.y)
    {
        AddReward(suspicionPenalty);
    }
    else
    {
        AddReward(suspicionBonus);
    }

    // 임계치 초과 시 게임 오버 처리
    if (suspicion >= maxSuspicion)
    {
        AddReward(-1f);
        EndEpisode();
    }
}
```

##### **설계 의도 / 코드 설명**

- AI가 단순히 도망만 다니는 것이 아닌 얼마나 자연스럽게 행동하는지를 목적으로 함
- 에이전트가 중력 방향에 수직으로, 그리고 바라보는 방향으로 이동할 때 보상을 주어 기계적인 움직임을 방지
- 술래의 정면에 노출되면 페널티를 부여하고, 시야 사각지대에 위치하면 보상을 주어 은폐 엄폐를 유도함
- AI가 너무 완벽하게 조용히 있으면 오히려 의심을 살 수 있으므로 적절한 수준의 의심도를 유지하도록 함

### PlanetGravity.cs

##### **개요**

게임의 무대인 작은 행성에서 캐릭터들이 표면에 붙어 이동할 수 있도록 하는 커스텀 중력 시스템

##### **핵심 코드**

```csharp
public Vector3 GetGravityDirection(Vector3 position)
{
    return (center - position).normalized; // 행성 중심을 향하는 방향 계산
}

private void ApplyGravity()
{
    foreach (var rb in affectedBodies)
    {
        if (!rb) continue;
        // 등록된 모든 Rigidbody에 행성 중심 방향으로 중력 가속도 적용
        rb.AddForce(GetGravityDirection(rb.position) * GravityStrength, ForceMode.Acceleration);
    }
}

public Vector3 GetSurfacePoint(out Vector3 normal)
{
    // 스폰 위치 등을 계산하기 위해 구체 표면의 좌표를 반환하는 로직
    // ... (Raycast를 통한 지형 보정 로직 포함)
    normal = Vector3.up;
    return center + Vector3.up * radius;
}
```

##### **설계 의도 / 코드 설명**

- PlanetGravity 싱글톤 클래스가 중력의 중심을 기준으로 각 물체의 위치에 따라 중력 방향을 실시간으로 계산함
- affectedBodies 리스트에 등록된 Rigidbody들에게 FixedUpdate마다 힘을 가하여 캐릭터가 행성 표면에 발을 붙이고 서 있을 수 있게 구현
- 캐릭터 스크립트에서 중력 벡터를 Up Vector로 사용하여 캐릭터가 항상 지면과 수직이 되도록 회전을 제어

### ConnectionManager.cs

##### **개요**

Unity Gaming Services(UGS)의 인증(Authentication), 로비(Lobby), 릴레이(Relay) 서비스를 통합하여 복잡한 네트워크 연결 과정을 단순화한 매니저

비동기 처리 흐름을 표준화하여 안정성을 높이고 예외 처리를 일원화함

> **전체 처리 흐름**  
> - **진입 (ConnectAsync)** → 접속 방식(Host/Client, Code/ID) 분기  
> - **흐름 제어 (HandleConnectionFlowAsync)** → 로딩 UI 표시 및 초기화 → 비동기 연결 로직 실행 (Delegate) → 예외 포착 및 사용자 알림  
> - **세션 생성/참여** → UGS 로그인 → Relay 할당 및 로비 생성 → NGO(Netcode) 전송 계층 연결  
>

#### 1. 연결 흐름의 추상화 (Template Method Pattern)
##### **핵심 코드**

```csharp
private async Task HandleConnectionFlowAsync(Func<Task<ISession>> sessionFunc)
{
    try
    {
        OnSessionConnectStart(); // 1. 시작 전처리 (로딩바 등)
        
        CurrentSession = await sessionFunc.Invoke(); // 2. 실제 연결 로직 (전략 패턴)
        
        // 연결 성공 후 처리는 각 전략 내부에서 수행
    }
    catch (Exception e)
    {
        NotifyUser(GetReadableErrorMessage(e)); // 3. 에러 핸들링 통합
        OnSessionConnectFail();
        throw;
    }
}
```

##### **설계 의도 / 코드 설명**

- '접속 시도 -> 로딩 -> 성공/실패'라는 공통 흐름을 하나로 묶고, 실제 접속 방식(방 생성, 코드로 참여 등)만 함수 파라미터(`sessionFunc`)로 교체하여 사용함
- 코드 중복을 줄이고, 모든 접속 시도에 대해 일관된 에러 처리를 보장함

#### 2. 세션 옵션 빌더 (Builder Pattern)

##### **핵심 코드**

```csharp
private async Task CreateSessionAsync(string sessionName, ...)
{
    // 복잡한 세션 설정값을 빌더로 정리
    var options = new SessionOptionBuilder()
        .Name(sessionName)
        .SeekerCount(1)
        .IsPrivate(true)
        .BuildCreate();

    await HandleConnectionFlowAsync(async () => 
        await MultiplayerService.Instance.CreateSessionAsync(options));
}
```

##### **설계 의도 / 코드 설명**
- 로비와 릴레이 생성에 필요한 수많은 매개변수를 `SessionOptionBuilder`를 통해 명시적이고 읽기 쉽게 구성함
- `IsPrivate`, `SeekerCount` 등 게임 특화 옵션을 직관적으로 설정하고 전달함

#### 3. 사용자 친화적 예외 처리

##### **핵심 코드**
``` csharp
private string GetReadableErrorMessage(Exception e)
{
    // 내부 예외 코드를 사용자 메시지로 매핑
    if (e is LobbyServiceException le)
    {
        switch (le.Reason)
        {
            case LobbyExceptionReason.RateLimited: return "잠시 후 다시 시도해주세요.";
            case LobbyExceptionReason.LobbyNotFound: return "방을 찾을 수 없습니다.";
        }
    }
    return "연결 중 오류가 발생했습니다.";
}
```

##### **설계 의도 / 코드 설명**
- `RequestFailedException` 같은 기술적인 에러 메시지를 그대로 보여주지 않고, 플레이어가 이해할 수 있는 문장으로 변환하여 UX를 개선함

### PlayManager.cs

##### **개요**

게임의 시작부터 종료까지의 전체 수명 주기(Lifecycle)를 관리하고, 서버 시간을 기준으로 글로벌 이벤트를 스케줄링하는 중앙 제어 시스템  
네트워크 지연이 발생하더라도 모든 클라이언트에서 공정하고 정확한 타이밍에 이벤트가 발생하도록 설계

> **전체 처리 흐름**  
> 초기화 (StartGameFlow) → 시드(Seed) 공유 및 맵 생성 → 역할(Role) 배정 및 로딩 종료  
> 타임라인 설정 (SetupEventTimeline) → 모드별 이벤트(미션, 토네이도) 등록  
> 게임 루프 (TickScheduler) → 서버 시간 동기화 → 스케줄러를 통한 정밀 이벤트 실행 → 승리 조건 체크  
> 게임 종료 (EndGame) → 결과 스냅샷 생성 → 로비 복귀

#### 1. 서버 권한 기반 게임 흐름 초기화

##### **핵심 코드**

```csharp
private void StartGameFlow()
{
    if (IsSessionOwner)
        sharedSeed.Value = Random.Range(0, 1_000_000);

    gameStartTimeServer = NetworkManager.ServerTime.Time;
    schedule.Clear();

    SetGameLoopRpc(true); // 게임 루프 활성화

    // 맵 생성, 역할 할당, 로딩 종료 등을 순차적으로 스케줄링
    SetupInitialSequence();
    SetupEventTimeline(GameManager.Instance.gameMode.Value);
}

```

##### **설계 의도 / 코드 설명**

- sharedSeed를 통해 모든 클라이언트가 동일한 절차적 맵을 생성하도록 보장함
- 게임 시작 시점을 기록하여 이후 발생하는 모든 이벤트의 기준점으로 삼음
- 초기화 과정을 단일 진입점으로 묶어 흐름을 파악하기 쉽게 함

#### 2. Tick Scheduler

##### **핵심 코드**

```csharp
private void TickScheduler(double now)
{
    for (int i = 0; i < schedule.Count; i++)
    {
        var task = schedule[i];
        if (now < task.executeTime) continue; // 실행 시간 미달 시 패스

        task.action?.Invoke(); // 등록된 델리게이트 실행

        if (task.repeating) task.executeTime += task.interval; // 반복 작업 갱신
        else toRemove.Add(i); // 일회성 작업 제거
    }
}
```

```csharp
AddRepeatingTask(20.0, 60.0, () => missionManager.ExecuteRandomMissionServer());
```

##### **설계 의도 / 코드 설명**

- Coroutine으로 구현을 했을 때, 시간이 밀리는 현상이 발생함
- 이를 위해 정확한 서버 시간(NetworkManager.ServerTime)을 비교하여 이벤트를 실행함
- 렉이나 프레임 드랍이 있어도 게임 내 이벤트(미션, 토네이도 등)는 절대 시간 흐름에 맞춰 정확히 발생함

#### 3. 모드별 이벤트 타임라인 구성

##### **핵심 코드**

```csharp
private void SetupEventTimeline(GameManager.GameMode mode)
{
    if (mode == GameManager.GameMode.HideSeek)
    {
        // 20초 후 첫 미션, 이후 60초마다 반복
        AddRepeatingTask(20.0, 60.0, () => missionManager.ExecuteRandomMissionServer());
    }
    else if (mode == GameManager.GameMode.LastStand)
    {
        // 최후의 1인 모드 전용 이벤트 (거대화)
        AddRepeatingTask(20.0, 40.0, GiantEvent);
    }

    // 공통: 30초 주기 토네이도 생성
    AddRepeatingTask(30.0, 30.0, () => tornadoManager.SpawnOnceServer());
}
```

##### **설계 의도 / 코드 설명**

- 게임 모드에 따라 실행되어야 할 이벤트들을 Start 시점에 미리 등록하여 관리함
- 하드코딩된 타이머 로직을 피하고, 타임라인을 데이터처럼 관리하여 유지보수를 용이하게 함

#### 4. 게임 종료 및 결과 처리

##### **핵심 코드**

```csharp
[Rpc(SendTo.Everyone)]
private void EndGameRpc(Role winner)
{
    if (IsSessionOwner)
    {
        var snapshot = BuildResultSnapshot(); // 현재 플레이어 상태 저장
        ShowResultRpc(winner, snapshot);
    }

    schedule.Clear(); // 남은 이벤트 취소
    SetGameLoopRpc(false);
    StartCoroutine(ReturnLobbyCo()); // 로비 복귀 카운트다운
}
```

##### **설계 의도 / 코드 설명**

- 게임 종료 시점의 데이터를 스냅샷으로 만들어 결과창에 전달함
- 플레이어가 나가거나 상태가 변해도 결과 화면에는 영향을 주지 않음
- 호스트가 종료 시퀀스를 주도하며, 일정 시간 후 자동으로 로비 씬으로 전환되도록 처리함

### RoleManager.cs

##### **개요**

게임 시작 시 참여한 플레이어들에게 역할을 배분

##### **핵심 코드**

```csharp
internal void AssignRole(int seed)
{
    // 시드 기반으로 난수 초기화하여 모든 클라이언트에서 동일 결과 보장 가능성 열어둠 (현재는 서버 권한 할당)
    Random.InitState(seed);

    var clients = NetworkManager.Singleton.ConnectedClientsIds
        .OrderBy(_ => Random.value) // 무작위 셔플
        .ToList();

    // 설정된 인원수만큼 술래(Seeker) 배정, 나머지는 Hider
    for (var i = 0; i < seekerCount; i++)
        SetRoleRpc(Role.Seeker, RpcTarget.Single(clients[i], ...));
}

```

##### **설계 의도 / 코드 설명**

- `seed` 값을 공유하여 서버와 클라이언트가 동일한 난수 시퀀스를 가질 수 있게 하거나 서버에서 일괄적으로 역할을 배정
- 게임의 공정성을 위해 역할 배정 로직을 서버 권한으로 격리함
- `RpcTarget.Single`을 통해 개별 클라이언트에게 역할을 통보하는 구조를 채택함

### CharacterBase.cs

##### **개요**

모든 캐릭터의 이동, 애니메이션, 상태 동기화를 처리하는 최상위 부모 클래스

##### **핵심 코드**

```csharp
protected void Move(Vector2 dir)
{
    // 소유권(Owner)이 없거나 상태이상(Stun/Dead) 중이면 조작 불가
    if (!IsOwner || isDead.Value || !CanMove) return;

    // 입력 벡터를 카메라/캐릭터 기준 좌표계로 변환하여 이동
    var moveDir = transform.forward * dir.y + transform.right * dir.x;
    rBody.MovePosition(rBody.position + moveDir * (currentSpeed * Time.fixedDeltaTime));
}

```

##### **설계 의도 / 코드 설명**

- 캐릭터의 공통 기능을 통합 관리하여 코드 중복을 최소화
- 네트워크 동기화 로직과 물리 이동 로직을 한곳에서 제어하여 유지보수 효율을 높임
- `NetworkTransform`을 상속받아 위치 동기화를 기본 지원함
- 입력 처리와 실제 이동 로직을 분리하여 AI와 플레이어가 동일한 이동 메커니즘을 공유하도록 함

### PlayerEntity.cs

##### **개요**

플레이어의 핵심 데이터(역할, 동물 타입, 이름)를 네트워크상에서 동기화하고 시각적 상태 변화를 총괄하는 데이터 클래스

##### **핵심 코드**

```csharp
// 역할(Role) 데이터가 변경되면 자동으로 외형/레이어 설정 로직 실행
private void OnRoleChanged(Role previousValue, Role newValue)
{
    switch (newValue)
    {
        case Role.Observer:
            gameObject.layer = LayerMask.NameToLayer("Observer");
            playerRenderer.UseObserverShader(); // 투명 쉐이더 적용
            break;
        // ... (Hider, Seeker, Fighter 설정)
    }

    // 로컬 플레이어라면 게임 매니저에도 알림
    if (IsOwner) GameManager.Instance.SetRoleRpc(OwnerClientId, newValue);
}

```

##### **설계 의도 / 코드 설명**

- `NetworkVariable`을 사용하여 데이터 변경을 감지
- 데이터와 프레젠테이션을 `OnValueChanged` 이벤트로 느슨하게 결합

### InteractableObject.cs

##### **개요**

게임 내 모든 상호작용 가능한 오브젝트(아이템, 장치 등)의 기반이 되는 추상 클래스

##### **핵심 코드**

```csharp
internal void Interact(ulong clientId)
{
    if (isBusy.Value) return; // 중복 상호작용 방지 (NetworkVariable)

    lastInteractorId = clientId;
    PlayHitFxRpc(); // 공통 효과 재생 (사운드/파티클)

    StartCoroutine(InteractCo()); // 각 구현체의 고유 로직 실행 (추상 메서드 아님, 가상 메서드)
}

```

##### **설계 의도 / 코드 설명**

- 템플릿 메서드 패턴을 적용하여 상호작용의 공통 흐름은 부모가 처리하고, 실제 효과는 자식이 구현하도록 함
- `isBusy` 네트워크 변수를 통해 동시 상호작용으로 인한 상태 불일치를 방지하여 상호작용 로직의 안정성과 확장성을 확보

### MissionManager.cs

##### **개요**

Hide & Seek 모드에서 도망자(Hider)들에게 미션을 부여하고 진행 상황을 관리하는 시스템임

##### **핵심 코드**

```csharp
public void ExecuteRandomMissionServer()
{
    if (!IsSessionOwner) return;

    var index = Random.Range(0, missions.Count);
    // 미션 타입과 목표치를 RPC로 전송
    AssignMissionRpc((int)mission.type, mission.description, mission.targetValue);
}

// 각 클라이언트에서 자신의 역할을 확인하고 미션 UI 활성화
private void AssignMissionRpc(...) { ... }

```

##### **설계 의도 / 코드 설명**

- 서버에서 랜덤한 미션을 선택하여 `AssignMissionRpc`로 모든 클라이언트에게 전파
- 해당 역할을 가진 클라이언트만 UI를 띄우고 미션 수행 상태를 체크
- 미션을 부여하여 게임의 템포를 조절하고 단순히 숨어있는 플레이를 지양하고 능동적인 움직임을 유도
