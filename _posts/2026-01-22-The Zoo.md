## 🤔 **문제 정의**

1. **플레이어와 구별하기 어려운 AI NPC를 구현할 수 있을까?**
   - 기존 NPC는 대부분 FSM 기반으로 동작하기 때문에 **플레이어와 행동 패턴이 명확하게 구분되는 한계가 존재**함
   - 행동 규칙이 고정되어 있기 때문에 상황에 따른 자연스러운 행동 변화를 만들기 어려움
   - 이러한 구조에서는 플레이어-NPC 간 구별이 어려운 상황을 만들기 어렵다고 판단함
2. **멀티 플레이 환경에서 플레이어들의 조작감을 쾌적하게 유지할 수 있을까?**
   - **Dedicated Server** 권한 기반 동기화 구조를 사용할 경우 입력 지연이 발생할 수 있으며, 이는 조작감에 직접적인 영향을 줌
   - 입력 지연을 최소화하면서 상태 동기화를 안정적으로 유지할 수 있는 **네트워크 권한 구조 선택이 필요**함
1. **네트워크 환경에서도 동일한 이벤트 타이밍을 유지할 수 있을까?**
   - Unity Coroutine 기반 타이머를 사용하여 미션과 이벤트 실행 시점을 관리했을 때, 이벤트 실행 시점이 밀리는 문제가 발생하여 **이벤트 실행 시점의 일관성을 보장하기 어려움**
   - 동일한 기준으로 이벤트를 실행할 수 있는 시간 동기화 기반 이벤트 관리 구조가 필요함

## 🥸 **설계 선택**

1. **플레이어와 구별하기 어려운 AI NPC를 구현할 수 있을까?**
   - **Unity ML-Agents**를 활용하여 강화학습 기반 Agent 구조를 적용함
   - 동일한 환경과 규칙 아래에서 보상 구조에 따라 행동을 학습할 수 있기 때문에 플레이어와 유사한 행동 패턴을 생성할 수 있다고 판단함
2. **멀티 플레이 환경에서 플레이어들의 조작감을 쾌적하게 유지할 수 있을까?**
   - 입력 반응성을 유지하면서도 상태 동기화를 안정적으로 수행할 수 있도록 **distributed authority** 토폴로지를 적용함
   - 플레이어가 자신의 입력과 상태 동기화에 대한 권한을 직접 가짐으로써 입력 반응성을 개선함
   - `NetworkVariable` / `Rpc` 등 상황에 맞는 동기화 방식으로 전체 게임 상태의 일관성을 유지하도록 함
1. **네트워크 환경에서도 동일한 이벤트 타이밍을 유지할 수 있을까?**
   - `NetworkManager`의 `ServerTime` 기준으로 이벤트 실행 시점을 관리하는 **scheduler 구조를 설계**함
   - 네트워크 환경에서도 동일한 기준으로 이벤트가 실행되도록 구성하여 **플레이어 간 이벤트 실행 시점의 일관성을 유지**함

   - 초기에는 기능 확장을 위해 상속 기반 구조를 사용하였으나 네트워크 동기화 구조와 결합되는 과정에서 기능 간 결합도가 높아지는 문제가 발생함
   - 이후 기능 단위로 컴포넌트를 분리하는 구조로 전환하면서 기능 추가와 수정 과정에서 영향 범위를 줄일 수 있었으며 멀티플레이 환경에서도 구조 확장에 유리한 방식임을 확인함
2. **NetworkVariable과 RPC의 역할을 분리하여 상태 동기화 구조를 구성함**
   - 지속적으로 유지되어야 하는 상태 정보는 NetworkVariable을 사용하고 공격이나 역할 변경과 같은 일회성 이벤트는 RPC를 사용하도록 동기화 구조를 분리함
   - 이를 통해 상태 동기화와 이벤트 동기화의 책임을 명확하게 구분할 수 있었으며 네트워크 동작 흐름을 구조적으로 관리할 수 있었음
3. **강화학습 Agent의 행동 품질은 보상 구조 설계에 크게 영향을 받음을 확인함**
   - 초기에는 단순 행동 기반 보상 구조를 사용하였으나 플레이어처럼 보이는 행동을 유도하기 위해 suspicion 기반 보상 구조로 재설계함
   - 이를 통해 불필요한 이동 패턴을 줄이고 시야 회피와 자연스러운 행동 선택이 가능하도록 학습 구조를 개선함

### 1. Distributed Authority 기반 동기화 구조 설계

```csharp
public NetworkVariable<GameMode> gameMode = new();
public NetworkVariable<int> readyCount = new();

public readonly NetworkList<PlayerData> players = new();

public NetworkVariable<int> hiderCount = new(0);
public NetworkVariable<int> seekerCount = new(0);
public NetworkVariable<int> fighterCount = new(0);
```

- 게임 모드, 준비 인원, 역할별 인원 수처럼 지속적으로 유지되어야 하는 값은 `NetworkVariable`로 관리함
- 플레이어 목록은 `NetworkList<PlayerData>`로 관리하여 입장, 퇴장, 역할 변경이 네트워크 상태로 동기화되도록 구성함
- 역할별 인원 수를 별도 `NetworkVariable`로 분리하여 승리 조건 검사 시 전체 리스트를 매번 순회하지 않고 상태값으로 판단할 수 있도록 함

---

```csharp
public override void OnNetworkSpawn()
{
    if (IsSessionOwner)
    {
        readyCount.Value = 0;
        players.OnListChanged += OnPlayerListChanged;
    }

    players.OnListChanged += OnPlayersChanged;
}
```

- `IsSessionOwner`에서만 역할 카운트 변경 로직을 처리하도록 분리함
- 모든 클라이언트는 `OnPlayersChanged`를 구독하여 로컬 캐시를 갱신하고, 세션 오너는 추가로 `OnPlayerListChanged`를 통해 역할 인원 수를 관리함

---

```csharp
private void OnPlayersChanged(NetworkListEvent<PlayerData> changeEvent)
{
    switch (changeEvent.Type)
    {
        case NetworkListEvent<PlayerData>.EventType.Add:
        case NetworkListEvent<PlayerData>.EventType.Insert:
        case NetworkListEvent<PlayerData>.EventType.Value:
            var pName = Util.GetPlayerNameWithoutHash(changeEvent.Value.name.Value);

            playerDict[changeEvent.Value.clientId] =
                (pName, changeEvent.Value.type, changeEvent.Value.role);
            break;

        case NetworkListEvent<PlayerData>.EventType.Remove:
        case NetworkListEvent<PlayerData>.EventType.RemoveAt:
            playerDict.Remove(changeEvent.Value.clientId);
            break;

        case NetworkListEvent<PlayerData>.EventType.Clear:
            playerDict.Clear();
            break;
    }
}
```

- `NetworkList` 변경 이벤트를 기준으로 로컬 `playerDict`를 갱신함
- `Add`, `Insert`, `Value`는 동일한 갱신 흐름으로 처리하고, `Remove`, `Clear` 상황까지 분기하여 네트워크 리스트와 로컬 캐시의 불일치를 줄이도록 구현함
- UI나 게임 로직에서는 `NetworkList`를 직접 순회하지 않고 `playerDict`를 참조할 수 있도록 캐싱 구조를 둠

---

```csharp
[Rpc(SendTo.Authority)]
internal void SetRoleRpc(ulong clientId, Role role)
{
    for (var i = 0; i < players.Count; i++)
    {
        var data = players[i];

        if (data.clientId != clientId) continue;

        data.role = role;
        players[i] = data;
        return;
    }
}
```

- 역할 변경은 `Rpc(SendTo.Authority)`로 권한 대상에서 처리되도록 구현함
- `NetworkList` 내부의 `PlayerData` 값을 직접 수정한 뒤 다시 할당하여 `Value` 변경 이벤트가 발생하도록 구성함
- 지속 상태는 `NetworkList`, 변경 요청은 `RPC`로 분리하여 처리함

### 2. 인게임 Session Lifecycle 구현

```csharp
public async Task ConnectAsync(ConnectionData data)
{
    try
    {
        switch (data.Type)
        {
            case ConnectionType.JoinById:
                await JoinByIdAsync(data.IdOrCode, data.Password);
                break;

            case ConnectionType.JoinByCode:
                await JoinByCodeAsync(data.IdOrCode, data.Password);
                break;

            case ConnectionType.Create:
                await CreateSessionAsync(data.SessionName, data.Password, data.IsPrivate);
                break;

            case ConnectionType.Quick:
                await QuickJoinAsync(data.SessionName);
                break;
        }
    }
    catch (SessionException e)
    {
        NotifyUser(GetReadableErrorMessage(e));
        OnConnectionFailed();
    }
    catch (Exception e)
    {
        NotifyUser(e.Message);
        OnConnectionFailed();
    }
}
```

- 세션 생성, 코드 참가, ID 참가, 빠른 참가를 `ConnectionType` 기준으로 분기함
- 연결 실패 시 `SessionException`과 일반 예외를 분리하여 사용자 알림과 실패 이벤트 처리를 공통화함
- 외부 UI에서는 `ConnectionData`만 전달하고 실제 접속 흐름은 `ConnectionManager`가 담당하도록 구성함

```csharp
private async Task HandleConnectionFlowAsync(
    Func<Task<ISession>> sessionFunc
)
{
    try
    {
        OnSessionConnectStart();

        CurrentSession = await sessionFunc.Invoke();
```

### 3. 강화학습 기반 Hider Agent 구현

```csharp
public override void CollectObservations(VectorSensor sensor)
{
    sensor.AddObservation(transform.up.normalized);
    sensor.AddObservation(transform.forward.normalized);
```

- Agent의 방향 벡터, 이동 입력, 시선 입력, 행동 가능 상태를 관측값으로 전달함

- `suspicion / maxSuspicion`으로 의심도를 정규화하여 학습 입력으로 사용함

---

```csharp
public override void OnActionReceived(ActionBuffers actions)
{
    var dActions = actions.DiscreteActions;

    MoveAction(dActions[0], dActions[1]);
    LookAction(dActions[2]);
    JumpAction(dActions[3]);
    SpinAction(dActions[4]);
    RunAction(dActions[5]);

}
```

- 이동, 시선 회전, 점프, 스핀, 달리기, 공격을 discrete branch로 분리함
- 신경망 출력값을 각각의 행동 함수에 매핑하여 실제 캐릭터 동작으로 연결함
- 행동 처리 이후 `HandleRewards()`를 호출하여 현재 행동 결과에 대한 보상을 계산함

---

```csharp
private void JumpAction(int action)
{
    if (action != 1) return;
    if (!CanMove) return;
    if (!CanJump) return;
    if (SpinHold) return;

    BroadcastAction(HiderActionType.Jump);

    suspicion = Mathf.Min(suspicion + gainJump, maxSuspicion);
    animator.SetTrigger(CharacterAnimator.JumpHash);
}
```

- 행동 실행 전 이동 가능 여부, 점프 가능 여부, 스핀 상태를 검사하여 불가능한 상태에서 행동이 실행되지 않도록 처리함
- 점프 행동이 발생하면 `BroadcastAction`으로 행동을 외부 listener에게 알림
- 점프는 눈에 띄는 행동으로 간주하여 의심도 증가값을 반영함

---

```csharp
private void HandleSuspicion()
{
    if (suspicion > 0f)
    {
        suspicion -= suspicionDecayPerSecond * Time.fixedDeltaTime;

        if (suspicion < 0f)
            suspicion = 0f;
    }

    if (suspicion < suspicionSafeZone.x ||
        suspicion > suspicionSafeZone.y)
    {
        AddReward(suspicionPenalty);
    }
    else
    {
        AddReward(suspicionBonus);
    }

    if (suspicion >= maxSuspicion)
    {
        AddReward(-1f);
        EndEpisode();
    }
}
```

- 의심도는 시간에 따라 감소하도록 처리하여 행동 이후 상태가 계속 누적되지 않도록 구현함

```csharp
private void Update()
{
    if (!IsSessionOwner || !gameLoop.Value) return;

    schedulerAccum += Time.deltaTime;

    if (schedulerAccum < SchedulerCheckInterval) return;

    schedulerAccum = 0f;

    var now = NetworkManager.ServerTime.Time;

    TickScheduler(now);
    UpdateCurrentTime(now);
}
```

- scheduler는 세션 오너이면서 게임 루프가 활성화된 경우에만 동작함
- `Time.deltaTime`으로 검사 주기를 누적하고, 일정 간격에 도달했을 때만 서버 시간을 읽어 처리함
- 이벤트 실행과 현재 시간 동기화를 같은 서버 시간 기준으로 처리함

```csharp
private void TickScheduler(double now)
{
    if (schedule.Count == 0) return;

    List<int> toRemove = null;

    for (int i = 0; i < schedule.Count; i++)
    {
        var task = schedule[i];

        if (now < task.executeTime) continue;

        task.action?.Invoke();

        if (task.repeating)
        {
            task.executeTime += task.interval;
        }
        else
        {
            toRemove ??= new List<int>();
            toRemove.Add(i);
        }
    }

    if (toRemove != null)
    {
        for (int i = toRemove.Count - 1; i >= 0; i--)
        {
            schedule.RemoveAt(toRemove[i]);
        }
    }
}
```

- 현재 서버 시간과 task의 실행 시간을 비교하여 실행 여부를 판단함
- 반복 이벤트는 실행 후 다음 실행 시간을 `interval`만큼 증가시킴
- 일회성 이벤트는 즉시 제거하지 않고 `toRemove`에 모은 뒤 역순으로 제거하여 순회 중 컬렉션 변경 문제를 방지함

```csharp
private void AddRepeatingTask(
    double firstOffsetSeconds,
    double intervalSeconds,
    Action action
)
{
    schedule.Add(new ScheduledTask
    {
        executeTime = gameStartTimeServer + firstOffsetSeconds,
        interval = intervalSeconds,
        repeating = true,
        action = action
    });
}
```

- 반복 이벤트는 게임 시작 서버 시간에 offset을 더해 최초 실행 시간을 계산함
- 미션, 토네이도, 모드별 이벤트를 동일한 등록 방식으로 처리할 수 있도록 구성함
