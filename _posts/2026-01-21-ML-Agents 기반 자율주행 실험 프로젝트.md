### 개선 방향 및 학습한 점

1. **환경·보상 설계의 중요성**
   - 강화학습 성능은 알고리즘보다 환경 구성과 보상 설계에 훨씬 중요하다는 점을 학습함
   - 단순 성공/실패 보상보다 행동의 질을 단계적으로 평가하는 보상 구조가 필요함
2. **관측 데이터 중심 설계**
   - 인식 정확도 자체보다 에이전트가 학습에 활용할 수 있는 안정적인 관측 정보 제공이 더 중요하다는 점을 배움
   - 카메라만 사용한다는 조건에서 영상 입력 자체의 품질과 일관성을 높이는 방향이 필요함
3. **이후 프로젝트에 반영**
   - 이후 The Zoo 프로젝트에서는 환경 이벤트와 보상 간의 인과 관계를 강화하도록 설계함
   - 학습이 일어날 수 있는 환경을 설계하는 것이 핵심이라는 점을 배움

### 기술적 한계와 문제점

1. **인식 파이프라인 한계**
   - 색상 필터 + Canny + Sliding Window 방식은 조명 변화, 가림, 급격한 곡선에 취약함
   - 차선 검출 결과가 불안정할 경우, 에이전트 관측 신뢰도가 급격히 저하됨
2. **Agent 보상 설계의 한계**
   - 전진 여부 중심의 단순 보상 구조로 인해 차선 유지, 복귀 행동, 안정 주행을 학습하지 못함
   - 차선 이탈 시 즉시 종료되는 구조로 실패 이후의 회복 행동 학습이 불가능
   - 보상과 실제 목표 간의 직접적인 연결이 부족함
3. **성능 문제**
   - RenderTexture → Texture2D → OpenCV Mat 변환 구조에서 불필요한 메모리 복사 비용 발생
   - 매 프레임 Resources.UnloadUnusedAssets() 호출로 GC 및 성능 저하 가능성 존재

##### **핵심 코드**

```csharp
public static Texture2D toTexture2D(this RenderTexture rTex)
{
    Texture2D tex = new Texture2D(rTex.width, rTex.height, TextureFormat.RGB24, false);
    var old_rt = RenderTexture.active;
    RenderTexture.active = rTex;

    tex.ReadPixels(new Rect(0, 0, rTex.width, rTex.height), 0, 0);
    tex.Apply();

    RenderTexture.active = old_rt;
    return tex;
}
```

### DrivingAgent.cs

#### **핵심 로직 개요**

본 코드는 Unity ML-Agents의 Agent를 상속하여, 연속 행동을 기반으로 차량을 제어하고 보상/종료 규칙을 통해 주행 행동을 학습하는 구조로 구현되었습니다.

에이전트는 매 스텝마다 2개의 연속 행동 값을 받아 차량의 전진과 조향을 결정하며, 단순한 보상 규칙과 명확한 종료 조건을 통해 초기 강화학습 실험을 검증하는 것을 목적으로 설계되었습니다.

#### 1. Agent 초기화 및 에피소드 설정

##### **핵심 코드**

```csharp
public override void Initialize()
{
    MaxStep = 10000;

    transform = GetComponent<Transform>();
    rigidbody = GetComponent<Rigidbody>();

    rigidbody.centerOfMass = new Vector3(0, -1f, 0);
}
```

```csharp
public override void OnEpisodeBegin()
{
    Resources.UnloadUnusedAssets();

    rigidbody.velocity = rigidbody.angularVelocity = Vector3.zero;
    transform.localPosition = new Vector3(1.8f, -4.7f, 0f);
    transform.localRotation = Quaternion.identity;
}
```

##### **설계 의도 / 코드 설명**

- 에피소드 시작 시 위치, 회전, 속도를 모두 초기화
- `MaxStep`을 크게 설정하여 한 에피소드 동안 충분한 주행 및 탐색이 가능하도록 함
- 무게 중심을 낮게 설정하여 차량 전복을 줄이고, 물리 안정성을 높임

#### 2. Action Space 설계 (Continuous Actions)

##### **핵심 코드**

```csharp
public override void OnActionReceived(ActionBuffers actions)
{
    var action = actions.ContinuousActions;

    Drive(action[0]);
    SteerVehicle(action[1]);
}
```

##### **설계 의도 / 코드 설명**

- 연속 행동 2개를 사용
  - `action[0]`: 전진/후진(가속)
  - `action[1]`: 좌우 조향
- Discrete Action 대신 Continuous Action을 사용하여 보다 부드러운 주행 제어를 학습 유도
- 최소한의 Action 구성으로 초기 학습 난이도를 낮추는 것을 목표로 함

#### 3. Heuristic (수동 조작) 구현

##### **핵심 코드**

```csharp
public override void Heuristic(in ActionBuffers actionsOut)
{
    var action = actionsOut.ContinuousActions;

    action[0] = Input.GetAxis("Vertical");
    action[1] = Input.GetAxis("Horizontal");
}
```

##### **설계 의도 / 코드 설명**

- 키보드 입력을 매핑하여 학습 이전 단계에서 차량 제어 및 물리 동작을 테스트

#### 4. 보상(Reward) 설계

##### **핵심 코드**

```csharp
if (action[0] >= 0.3f)
{
    reward = 1f;
}
else
{
    reward = -1f;
}

AddReward(reward / MaxStep);
```

##### **설계 의도 / 코드 설명**

- 차량이 일정 수준 이상의 전진 입력을 유지하도록 유도하기 위한 단순한 보상 구조
- 보상을 `MaxStep`으로 나누어 매 스텝마다 누적함으로써, 장시간 주행을 유지하는 행동을 유도
- 초기 실험 단계에서 보상 구조를 단순화하여 학습 흐름을 빠르게 확인하는 것을 목표로 함
